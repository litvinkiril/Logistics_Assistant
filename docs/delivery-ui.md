# Экран рейса

Раздел «Доставки» доступен по `/index.html#/deliveries`. Показывает рейсы без
ответственного из `GET /api/delivery-orders/unassigned?offset=0`, по 10 за страницу.
Любой рейс можно открыть по номеру, в том числе уже назначенный.

Во вкладке «Мои рейсы» (`/index.html#/deliveries?tab=mine`) используется
`GET /api/delivery-orders/mine`. Пользователя определяет сервер по сессии.
В карточках показана отметка «Вы ответственный», из карточки рейса можно вернуться
к той же вкладке. Обновление страницы сохраняет выбранную вкладку.
При пустом списке есть кнопка перехода к свободным рейсам.
Текущий endpoint возвращает до 10 рейсов без параметра `offset`; поэтому
для «Моих рейсов» кнопка догрузки не показывается, при 10 записях отображается
подпись об ограничении. Пагинация свободных рейсов работает как прежде.

Для доступа требуется вход. При отсутствии сессии открывается форма входа,
а после успешного входа пользователь возвращается к исходному разделу или рейсу.

## Взять рейс на себя

Кнопка доступна в карточках свободных рейсов и внутри рейса без ответственного.
Вызывает существующий `PATCH /api/delivery-orders/{id}/assign` с cookie-сессией
и свежим CSRF-токеном. Пользователя сервер определяет из сессии.

На время запроса кнопка блокируется. После назначения из списка открывается
карточка рейса с отметкой «Вы ответственный за рейс»; после возврата к списку
назначенный рейс в нём отсутствует. Внутри карточки отметка обновляется сразу.
Существующее поле `status` эта операция не меняет.

При `409` обновляются данные списка или назначенного ответственного и выводится
сообщение об уже занятом рейсе. При `401` открывается вход. Сетевые ошибки
показываются на странице; повторное нажатие во время запроса не отправляет
дублирующую операцию.

`DeliveryAssignmentApiTests` проверяет назначение текущего пользователя,
исчезновение рейса из свободных и защиту от перезаписи при одновременном назначении.

Карточка `/index.html#/deliveries/1` загружает
`GET /api/delivery-orders/1`: `{ order, items }`. Также поддерживается ответ
непосредственно списком `DeliveryProductDto[]`; в этом случае показывается только
состав груза, без карточки автомобиля.
Строки объединяются по `productId`; количество всех типов упаковки и точек
назначения суммируется. Единица измерения — физические коробки.

Поддерживаются поля текущих позиций `boxQuantity`, `inTruckBoxQuantity`
и товарных итогов `requiredQuantity`, `inTruckQuantity` внутри `items` либо
непосредственно в списке ответа.
Сервер должен отдавать один формат целиком, без дублирования тех же остатков
в подробных позициях и итогах. Отсутствующее количество считается ошибкой ответа.

Товар с нулевым планом и положительной загрузкой остаётся в списке с отметкой
«Вне плана». Текущий сервер возвращает только позиции плана: для незапланированного
груза ещё нужна независимая связь коробки с рейсом и изменение серверного запроса.
Фронт не получает незапланированные коробки из других рейсов или складских остатков.

Есть поиск по названию и ID, фильтры нехватки, внепланового груза и всех расхождений.
«Осталось загрузить» суммирует нехватку отдельно по товарам: избыток одного товара
не компенсирует отсутствие другого. Кнопка «Обновить» повторно запрашивает данные.

Проверка группировки, нулевых значений, внепланового груза и больших ID:

```powershell
node --test scripts/test-delivery-ui.mjs
```
