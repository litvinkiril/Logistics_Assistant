# Фронтенд логистического помощника

Интерфейс находится в `Logistics_Assistant/wwwroot` и работает с существующими
контроллерами из того же приложения. Дополнительный сервер, Node.js и установка
пакетов для запуска не нужны. Основные файлы: `index.html`, `css/site.css`,
`js/app.js`, `assets/icons.svg`, `assets/logo.svg`.

## Запуск

Из папки решения:

```powershell
dotnet run --project Logistics_Assistant/Logistics_Assistant.csproj --launch-profile http
```

Открыть `http://localhost:5114/index.html`. При запуске проекта в Visual Studio
профили `http` и `https` также открывают `index.html`.
Используется обычное подключение приложения к PostgreSQL. Интерфейс не создаёт
таблиц и не выполняет миграций. Назначение рейса, смена этапов и погрузка
записывают изменения через API приложения.

Корневой маршрут `/` сохранён: он возвращает информацию об API в JSON.

### Ошибка сжатия при запуске из Visual Studio

Если при открытии HTML возникала ошибка `InvalidDataException: The archive
entry was compressed using an unsupported compression method` со стеком
`Microsoft.AspNetCore.Watch.BrowserRefresh.ResponseStreamWrapper`, это
соответствует известному конфликту Browser Link с автообновлением и сжатыми
статическими файлами в .NET 10. В обоих профилях `launchSettings.json` добавлено
рекомендованное Microsoft исключение:

```json
"ASPNETCORE_HOSTINGSTARTUPEXCLUDEASSEMBLIES": "Microsoft.WebTools.BrowserLink.Net"
```

Оно исключает только Browser Link при локальном запуске. Сжатие файлов,
автообновление dotnet watch и рабочая конфигурация приложения сохраняются.
После изменения нужно полностью остановить отладку и запустить проект заново,
затем обновить страницу через Ctrl+F5. Переменная применяется при старте процесса.
Источник: https://github.com/dotnet/aspnetcore/issues/64453

## Экраны

- `index.html#/products`: поиск по части названия, ID или полной ссылке;
  результаты загружаются порциями по 10, показывают реальные остатки.
- `index.html#/products/1`: карточка товара, общие остатки, распределение по
  складам и ПВЗ, переход к выбранной точке и ссылка на страницу товара.
- `index.html#/points`: справочник точек с поиском по названию, городу и адресу,
  фильтрами «Все / Склады / ПВЗ» и статусом активности.
- `index.html#/points/1`: адрес и координаты точки, ссылка на Яндекс Карты,
  проверка наличия конкретного товара по названию, ID или URL. Географическая
  подложка в карточке — условная схема; реальная карта открывается по ссылке.
- `index.html#/deliveries`: свободные и назначенные рейсы с догрузкой списка.
- `index.html#/deliveries/1`: назначение ответственного, смена этапов, погрузка
  по ID или ссылке, план по упаковкам и пунктам назначения.
  Подробности и ограничения — в [delivery-ui.md](delivery-ui.md).

Поиск и выбранные фильтры сохраняются в адресе страницы. Кнопки браузера
«Назад / Вперёд» и обновление страницы поддерживаются. Шесть недавних поисков
товаров сохраняются в localStorage текущего браузера; есть очистка истории.
При переходе между экранами устаревшие запросы отменяются. Ошибки, отсутствие
результатов и недоступность базы отображаются отдельными состояниями.

На телефоне используется нижняя навигация, результаты идут сразу после формы
поиска. На компьютере доступны боковое меню и раскладка в несколько колонок.
Иконки и стили локальные; внешние шрифты и изображения не загружаются.

## Ограничения текущего API

Полного списка товаров одной точки в API нет. Поэтому карточка точки проверяет
наличие найденных товаров через `GET /api/products/{productId}/stock/{pointId}`;
полнота складского ассортимента и его суммарные показатели не заявляются.
API товара содержит только ID, название и URL. Фотографии, вес, упаковка и
признаки хрупкости не выдумываются: вместо фотографии используется иконка.

## Первоначальное исправление серверного кода

В `ProductsController.GetStockAtPointAsync` вызов
`_points.SearchProductStockAtPointAsync` заменён на
`_search.SearchProductStockAtPointAsync`: этот метод уже существует именно
в `ProductSearchService`. Без замены исходный проект не собирался (CS1061).
Маршруты, модели, сервисы, настройки базы и миграции не изменены.

## Проверка

Проект собирается без ошибок и предупреждений. Все 83 существующих теста
пройдены с отдельной временной PostgreSQL через
`scripts/test-logistics-points.ps1 -AllTests`. В браузере на реальной базе
проверены поиск, остатки товара, переход к складу, наличие товара в точке,
фильтры, пустые результаты и мобильная раскладка.
