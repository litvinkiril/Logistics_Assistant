# Погрузка физической коробки

`POST /api/delivery-orders/{orderId}/boxes/load`

По ID коробки:

```json
{
  "orderItemId": 15,
  "physicalBoxId": 42
}
```

По QR-ссылке:

```json
{
  "orderItemId": 15,
  "url": "https://example.test/boxes/42"
}
```

Нужно указать ровно один идентификатор: положительный `physicalBoxId` или
непустой `url`. Пробелы по краям URL обрезаются. URL используется для поиска
в `physical_boxes`, запрос по этому адресу в интернете не выполняется.
`orderItemId` — существующая позиция именно этого рейса; она определяет тип
упаковки и точку назначения. Коробки вне существующего плана этот endpoint
не загружает.

Пользователь определяется по cookie-сессии и должен быть ответственным за рейс.
Для запроса нужен свежий `X-CSRF-TOKEN` из `GET /api/auth/csrf` в той же сессии.
Рейс должен иметь статус `loading`, а `SourcePointId` — указывать на активный
склад. Коробка должна находиться на этом складе и соответствовать типу упаковки
позиции плана. Резервирование под другую позицию запрещает погрузку.

## Изменения в БД

Одна транзакция с уровнем Serializable:

1. Меняет `PhysicalBox.Status` на `InTransit`, очищает `CurrentPointId`
   и записывает `CurrentOrderItemId`.
2. Создаёт `BoxMovement` с операцией `Load`, исходным складом,
   пользователем и временем UTC.
3. Пересчитывает `WarehouseProducts.Quantity` для товара на исходном складе.

Остаток означает число **полных комплектов товара**: для каждого типа упаковки
считается число физических коробок на складе, делится на `QuantityPerProduct`
с округлением вниз, затем берётся минимум по всем типам. Поэтому для применения
этого расчёта все физические складские коробки должны быть учтены в `PhysicalBoxes`.
Если строки агрегированного остатка ещё нет, она создаётся, в том числе с нулём.
Плановое количество позиции и статус рейса погрузка не меняет.

Два сохранения выполняются в одной транзакции. Ошибка при записи остатка
откатывает также перемещение коробки и запись истории.
Повторный запрос для уже погруженной в ту же позицию коробки при статусе рейса
`loading` возвращает `204`, не создавая дубликат движения.

## Ответы

| Код | Значение |
| --- | --- |
| 204 | Коробка погружена или уже находится в этой позиции рейса |
| 400 | Неверные идентификаторы или отсутствует/неверен CSRF-токен |
| 401 | Нужен вход |
| 403 | Пользователь не является ответственным |
| 404 | Рейс, позиция или коробка не найдены |
| 409 | Не подходит статус, склад, упаковка, резервирование либо возник конфликт конкурентных изменений |

При конкурентном изменении нужно обновить данные и повторить сканирование.
Поле пользователя из тела запроса не используется.

## Проверка

```powershell
.\scripts\test-logistics-points.ps1 -AllTests
```

`BoxLoadingTests` проверяет HTTP-маршрут, вход и CSRF, выбор по ID/URL,
права ответственного, склад, статус, позицию и упаковку, повторные сканирования,
конкурентную погрузку, пересчёт полных комплектов и откат при сбое сохранения остатка.
Тесты используют отдельный PostgreSQL, не рабочую БД.
